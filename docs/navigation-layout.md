# 全站导航与响应式布局

## 页面入口

所有页面共用 `assets/navigation.js` 和 `assets/workspace.css`，主菜单顺序固定：

| 页面 | 地址 | 学科范围 |
| --- | --- | --- |
| 首页 | `/` | 当前选择的学科 |
| 题目分析 | `/analyze/` | 仅数学，支持文字与图片 |
| 知识图谱 | `/explore/` | 当前选择的学科 |
| 学习诊断 | `/diagnose/` | 当前选择的学科 |
| 孩子档案 | `/children/` | 全部学科 |
| 盲区与历史 | `/children/history.html` | 全部学科，可在页内筛选 |

表中的地址相对于应用根目录。导航通过脚本地址推导根路径，因此部署在 GitHub Pages 项目子目录时也能生成正确的链接。菜单使用普通链接，支持浏览器前进、后退和新标签页。

## 学科与孩子状态

- 首页、知识图谱和诊断的学科下拉框使用统一的 `subject` 参数。切换页面保留所选学科；当前标签页使用 `sessionStorage` 记住选择，新会话默认数学。
- 显式 `subject` 优先。旧题目深链接没有 `subject` 时，从 `target` 或知识点 hash 的 ID 前缀判断学科，再回退到记忆值。数学 ID 不会因为之前看过英语而误加载英语数据。
- 切换学科会清除旧的目标、章节、年级、册次、演示和 hash 参数，回到当前页面的新学科入口，避免旧题目被带到新学科。
- 题目分析与档案类页面不追加无效学科参数。题目分析始终标注仅数学；从分析结果进入诊断时，由数学知识点 ID 确定学科。
- 档案页与历史页是两个独立菜单，高亮不再混用。历史页选择孩子会同步当前孩子；选定具体学科后，诊断入口也同步该学科。
- 主菜单切换到页面入口，不携带上一页的题目或筛选条件；需要直接进入具体题目时，使用页内的“诊断”“再测”等深链接。

## 桌面与手机布局

导航、标题区域和主要工作区使用一致的最大宽度 1560px。桌面主菜单完整展示，手机主菜单可横向滚动，并自动将当前页面的菜单项滚入视野。

| 页面 | 桌面布局 |
| --- | --- |
| 首页 | 学习入口与使用步骤并排，统计和年级卡片铺满工作区 |
| 题目分析 | 左侧输入题目，右侧核对考点及学习路径 |
| 知识图谱 | 目录、局部先修图和知识点详情三栏 |
| 诊断开始页 | 左侧档案与设置，右侧知识点搜索和章节目录 |
| 诊断答题 | 使用较宽的独立答题区域，避免无限拉长题目行宽 |
| 诊断结果 | 根因 / 不稳、学习路径 / 路径图等内容分栏，总览和答题记录使用整行 |
| 孩子档案 | 左侧档案卡片，右侧添加 / 编辑表单与备份恢复 |
| 盲区与历史 | 薄弱知识与历史记录分栏 |

窄屏按页面内容自动改为单栏；知识图谱保留手机目录开关，表单和原有诊断逻辑不变。浅色和深色主题使用同一套颜色变量。打印诊断结果时隐藏导航并恢复单栏。

## 修改入口与验证

主菜单、学科上下文和链接构造只修改 `assets/navigation.js`。各页面通过 `data-navigation-page` 声明页面身份，不能再各自遍历导航链接追加参数。全站尺寸和导航样式放在 `assets/workspace.css`，页面内部控件样式仍由各页 CSS 管理。

首页的题目分析、诊断和图谱按钮分别使用独立 ID，不能按“第一个非主按钮”定位，避免新增按钮后出现错跳。

```bash
npm test
python3 scripts/test-workspace-browser.py
python3 scripts/test-question-browser.py
```

浏览器脚本需要 Python Playwright 和本机 Chrome，可通过 `--chrome` 指定路径。工作台测试覆盖全部 36 种主菜单跳转、十个学科的数据与入口、前进 / 后退、切换学科清理旧参数、分析进入数学诊断、档案与历史状态衔接，以及浅色 / 深色的桌面和手机布局。默认截图输出到 `/tmp/cnm-workspace-browser`。

部署后执行 `git pull origin feat/question-knowledge-analysis`，在浏览器强制刷新以加载共享导航和新样式；本次前端改动无需重启 Node 服务。离线缓存版本同步更新。
